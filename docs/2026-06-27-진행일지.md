# 2026-06-27 진행일지 (CARLA 카메라 렌더링 병목 원인 분석)

## 완료한 작업

### 1. 베이스라인 평가 재시도 및 센서 타임아웃 문제

이전에 백그라운드로 돌려놓은 베이스라인 평가가 모두 센서 타임아웃(SensorReceivedNoData)으로 실패한 상태로 종료되어 있었음을 확인.

frame_rate 2Hz에서 타임아웃이 발생하는 원인을 분석:
- frame_rate는 CARLA 시뮬레이션의 tick 속도를 결정
- 동기 모드(synchronous_mode)에서 CARLA는 에이전트가 응답할 때까지 매 tick마다 대기
- frame_rate를 낮추면 tick 간격이 늘어나 센서 데이터 공급이 줄어듦
- frame_rate를 20Hz로 복원

---

### 2. CARLA CPU 사용률 이상 현상 발견

leaderboard + LMDrive 에이전트 연결 시 CarlaUE4 프로세스가 CPU 1000~1200%까지 치솟는 현상 확인. 반면 CARLA 단독 실행(idle) 시에는 100% 수준으로 정상.

GitHub Issue #9250 확인 결과, 이는 CARLA 0.9.15의 알려진 공식 버그:
- 동기 모드에서 클라이언트 응답을 기다릴 때 busy-wait(스핀락) 방식 사용
- CARLA 개발자가 직접 100us sleep을 추가해 테스트한 결과 CPU 100%에서 5%로 20배 개선 확인됨
- 네이티브 Linux에서도 동일하게 발생하는 CARLA 자체의 설계 결함이며 WSL2 한정 문제가 아님

---

### 3. 진짜 병목 원인 발견: GPU 렌더링이 CPU 소프트웨어 렌더링으로 폴백

단계적으로 격리 테스트를 진행하여 정확한 병목 지점을 특정:

테스트 결과 (20틱 기준 소요시간):
- CARLA 순수 tick (센서 없음): 0.32초
- LiDAR 센서만 부착: 0.60초
- RGB 카메라 센서 부착 (800x600): 17.97초
- RGB 카메라 센서 부착 (200x150, 저해상도): 14.74초

카메라 센서만 압도적으로 느리며, 해상도를 낮춰도 개선이 미미함. 해상도 문제가 아니라 렌더링 파이프라인 자체의 문제로 판단.

glxinfo와 vulkaninfo로 그래픽 드라이버 상태 확인:
- OpenGL renderer string: llvmpipe (LLVM 21.1.8, 256 bits)
- deviceName: llvmpipe (LLVM 21.1.8, 256 bits)
- driverID: DRIVER_ID_MESA_LLVMPIPE

/usr/share/vulkan/icd.d/, /usr/lib/wsl/lib/ 확인 결과 NVIDIA용 Vulkan ICD 파일(nvidia_icd.json), OpenGL 렌더링 라이브러리(libGLX_nvidia.so)가 전혀 존재하지 않음. CUDA 연산용 라이브러리(encode, ml, opticalflow)만 존재.

결론: CUDA(PyTorch GPU 연산)는 정상 작동하지만, Vulkan/OpenGL(CARLA 카메라 렌더링)이 GPU 가속 없이 CPU 소프트웨어 렌더링(llvmpipe)으로 폴백되고 있음.

---

### 4. 외부 사례 확인 (동일 버그 검증)

NVIDIA 개발자 포럼 및 GitHub 이슈 검색을 통해 동일 증상의 외부 보고 확인:
- NVIDIA Developer Forums (2026-02): RTX 5070 Ti(Mobile) + 드라이버 591.86 + WSL2 환경에서 CUDA는 정상이나 Vulkan 초기화 완전 실패 보고 (우리 드라이버 버전과 정확히 일치)
- NVIDIA Developer Forums (2025-09): RTX 5070 Ti + WSL2에서 CUDA는 정상이나 OpenGL 미작동, /usr/lib/wsl/lib에 CUDA/encode/opticalflow 라이브러리만 존재한다는 동일 증상 보고
- microsoft/wslg Issue 1312: WSL2에서 NVIDIA OpenGL 로드 실패, libnvidia-gl.so 누락, Vulkan ERROR_INCOMPATIBLE_DRIVER 보고

RTX 50 시리즈(Blackwell) + WSL2 조합에서 NVIDIA가 아직 그래픽 렌더링 드라이버 패스스루를 제대로 지원하지 못하는 알려진 미해결 버그로 판단됨.

### 5. 네이티브 Ubuntu 듀얼부팅 결정 및 사전 백업

WSL2에서는 환경설정으로 해결 불가능한 드라이버 문제로 확인되어, 네이티브 Ubuntu 듀얼부팅을 결정.

이전 작업 환경을 그대로 이전하기 위해 사전 백업 진행:
- conda env export > /mnt/c/LMDrive/environment_export.yml
- pip freeze > /mnt/c/LMDrive/pip_freeze.txt

수정한 핵심 코드 파일 9개 별도 백업 (/mnt/c/LMDrive_backup_modified_files/):
- lmdriver_config.py, lmdriver_agent.py
- leaderboard_evaluator.py, route_manipulation.py (leaderboard, scenario_runner 양쪽)
- sensor_interface.py, drive.py, run_evaluation.sh
- atomic_behaviors.py, atomic_trigger_conditions.py

모델 가중치 및 CARLA 설치 파일은 C드라이브에 위치하므로 듀얼부팅 시 파티션을 분할해도 재다운로드 없이 그대로 활용 가능 (C드라이브 포맷 금지 확인).

## 트러블슈팅 기록

문제: 센서 타임아웃 (SensorReceivedNoData)
원인: frame_rate를 2Hz로 낮춰 tick 간격 증가
해결: frame_rate 20Hz로 복원

문제: CarlaUE4 CPU 1200%
원인: CARLA 0.9.15 동기 모드 busy-wait 버그 (공식 확인된 이슈)
결론: 네이티브에서도 발생하는 CARLA 자체 결함, 우회 불가

문제: 카메라 센서만 56배 느림
원인: NVIDIA Vulkan/OpenGL ICD 누락, llvmpipe 소프트웨어 렌더링 폴백
결론: WSL2 드라이버 한계, 네이티브 Ubuntu 전환 결정

문제: -RenderOffScreen 옵션 미적용
원인: run_evaluation.sh에서 공백 누락으로 옵션이 이전 옵션에 붙어버림
해결: 공백 추가로 수정 (단, 근본 해결책은 아니었음)

## 핵심 결론

1. GPU 연산(CUDA)과 GPU 렌더링(Vulkan/OpenGL)은 완전히 별개의 드라이버 경로이며, WSL2 + RTX 5070 Ti 조합에서는 전자만 지원되고 후자는 미지원 상태
2. 이는 사용자 설정 문제가 아니라 NVIDIA의 WSL2 드라이버 패스스루 자체의 미해결 버그 (2025-09, 2026-02 외부 보고 사례로 검증됨)
3. CARLA처럼 카메라 렌더링이 핵심인 시뮬레이터는 WSL2 환경에서 정상적인 속도로 구동 불가능
4. 네이티브 Ubuntu 듀얼부팅이 유일한 해결책으로 판단되어 환경 백업 후 전환 진행
